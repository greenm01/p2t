# Stress Fixture Profile

## Fixture Set

The fixtures are blank-separated multi-ring `.dat` files: the first ring is the
outer contour and the remaining rings are holes. The adversarial stress family
is generated by `tests/fixtures/stress/gen_fixture.py`; the matched organic
control is generated by `tests/fixtures/organic/gen_organic.py`. Both generators
validate rounded output coordinates before writing so invalid fixtures do not
enter the benchmark set.

| Fixture | Outer pts | Holes | Total pts | Triangles | Area error |
| --- | ---: | ---: | ---: | ---: | ---: |
| stress-small | 244 | 36 | 532 | 602 | 0 |
| stress-mid | 724 | 144 | 1,876 | 2,162 | 0 |
| stress-large | 1,044 | 287 | 3,340 | 3,912 | 0 |
| organic-large | 1,618 | 287 | 3,340 | 3,912 | 0 |

The public safe path succeeds on all fixtures. Tests sum emitted triangle areas
and compare against `outer area - hole areas`, so the check exercises the
triangulator output rather than only the input loader. The triangle-count check
uses `ring vertices + 2 * holes - 2`, which is valid here because these fixtures
use only ring vertices and insert no Steiner/interior points. If the area check
passes but this count fails on a future fixture, first check whether Steiner or
interior points were inserted.

## Front Hash Result

These fixtures are useful because they stress the front hash with dense
non-uniform x buckets and many holes. On the champion path, the default hash cuts
locate work substantially:

| Fixture | Config | Locate steps | Best raw us/run | Median raw us/run |
| --- | --- | ---: | ---: | ---: |
| stress-small | no front hash | 4,295 | 34.90 | 35.29 |
| stress-small | default hash, factor 2 | 1,803 | 36.38 | 37.66 |
| stress-mid | no front hash | 18,766 | 142.20 | 142.99 |
| stress-mid | default hash, factor 2 | 7,964 | 147.15 | 148.00 |
| stress-mid | bucket factor 4 | - | 143.29 | 152.13 |
| stress-large | no front hash | 36,151 | 247.86 | 255.15 |
| stress-large | default hash, factor 2 | 13,231 | 255.71 | 262.08 |
| stress-large | bucket factor 4 | - | 256.23 | 265.49 |

The per-lookup histograms say the hash hints are good: stress-small hit 529 of
531 point events, stress-mid hit 1,871 of 1,875, and stress-large hit 3,334 of
3,339. Direct hits have a fat tail on mid/large (`p99=64`), but scan hits stay
short (`p99=16` on mid, `p99=8` on large).

The wall-time result is different: at 532 points, maintaining and probing the
bucket index costs more than the saved front walks. The same net-negative
pattern persists on the valid mid and large stress fixtures. This is not a
hint-quality failure; it is the adversarial x-density and periodic comb geometry
finding a real hash-hostile case.

## Organic Control

`organic-large` holds the large stress fixture's point count and hole count
constant (`3340` points, `287` holes) while removing the comb's x-density
gradient and axis-aligned periodicity. The boundary is organic and the holes are
uniformly scattered.

| Fixture | Config | Locate steps | Best raw us/run | Median raw us/run |
| --- | --- | ---: | ---: | ---: |
| organic-large | no front hash | 119,863 | 300.36 | 302.27 |
| organic-large | default hash, factor 2 | 12,685 | 229.87 | 231.34 |

On this matched organic control, the front hash fires the "hash wins" branch:
best time improves from `300.36` to `229.87 us/run` (+23.5%), and median time
improves from `302.27` to `231.34 us/run` (+23.4%). The stats explain why:
no-hash locate steps are 119,863, while hash-on locate steps drop to 12,685
(9.4x fewer). The front hash hit every point event (`3339` hits, `0` misses),
with direct-hit `p99=32` and scan-hit `p99=32`.

This resolves the ambiguity in the adversarial family: uniformly distributed
hole density alone is not the cause of the stress-large loss. At the same point
and hole count, organic geometry is strongly hash-positive; the stress-family
loss is attributable to the engineered x-skew/periodicity. Pathologically
clustered holes could still reintroduce local x-skew, but that is a separate
case from the default-policy question tested here.

## Current Decision

Do not change the default front-hash policy. Raising `FrontHashMinPoints` or
disabling the hash for hole-heavy shapes would overfit to the adversarial comb
family and regress known wins such as `large-shape`, the Nazca fixtures, and the
matched organic-large control.

Keep the champion/default path unchanged. Bucket factor 4 remains only a tuning
breadcrumb: it reduces locate steps in stats runs, but timing does not justify a
default change across the valid stress suite.
